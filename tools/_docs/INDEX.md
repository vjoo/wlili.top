## 二、分层铁律（新内容先判断归属，再动笔）

| 内容类型 | 归属 | 判定 |
|---|---|---|
| 跨页面通用、长期稳定的规范（令牌 / 组件 / 结构 / 安全 / 部署） | **主指南** 对应章 | 3 个以上页面适用 |
| 只对某个模块有效的约定、专属组件、算法规则 | **`mod-*.md`** | 只服务 1~2 个页面 |
| 类名 / 函数名 / 选择器 / 「改哪里」清单（**易腐**） | **`mod-*.md`** | 会随代码漂移 |
| 「为什么会有这条规则」的事故叙事 | **`incidents.md`** | 只有解释价值 |
| 工具清单、文件树、图标色板等**可从配置派生**的清单 | **不写文档** → 读 `tools.json` / 目录 | 能自动得到就不手抄 |

## 三、防膨胀机制（硬约束）

1. **体积阈值（按字符数）**：主指南 **≤ 32,000 字符**、后台规范 ≤ 25,000 字符、单个 `mod-*.md` ≤ 15,000 字符。超阈值时必须把内容**下移**，而不是继续加章节。
2. **单条规则 ≤ 6 行**；写不下就说明它该进模块文档或事故档案。
3. **主指南章节清单封闭**：新增内容只能进已有章节；确需新章 → 先确认它是"跨页面通用"的，并同步更新本文件的「按任务找文档」表。
4. **不写易腐信息**：主指南/后台规范里**禁止**出现类名清单、函数名清单、行号 —— 这些只在 `mod-*.md`；`mod-*.md` 里也禁止写行号（用 Grep 锚点）。
5. **代码反指文档**：每个模块在代码里有边界注释指向对应 `mod-*.md`（见 `admin.html` 模块分隔注释），保证"读代码的人能发现文档"。
6. **自查命令**（改完文档跑一次）：
   ```bash
   python .workbuddy/tools/docs_audit.py      # 体积 / 死链 / 章节清单 / 易腐信息告警
   ```
